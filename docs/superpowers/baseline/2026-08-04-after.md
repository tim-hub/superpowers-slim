# After — post-rewrite measurements and comparison

**Tree measured:** four configurations, see the table
**Claude Code:** 2.1.223
**Originally written:** 2026-08-04
**Re-measured:** 2026-08-07 on a corrected harness

## Verdict

The 2026-08-04 numbers in this file measured the harness, not the skill set. They are replaced below,
and the conclusion they supported is refuted rather than merely unsupported.

Three defects invalidated them. The agent's working directory contained `superpowers-tests`, which cued
the very skill call the test was sampling — varying only the directory name gave 6/6 fired with the
string present against 0/15 with a neutral name. The runs inherited `~/.claude`, so personal skills
sharing the plugin's names answered instead of the plugin, and the pass condition accepted an unprefixed
match. And every run happened inside a command sandbox where the plugin's SessionStart hook fails with
EPERM, so the hook-present configuration measured a broken hook.

This file's earlier reasoning that the EPERM was "a uniform degradation, not the discriminator" was the
specific error: uniform across rows it may have been, but it destroyed the one variable the
hook-present row existed to test.

**The session-start hook is the entire autotrigger mechanism.** With it, `brainstorming` fires 15 out of
15 and never writes a file first. Without it, on the same 14 skills with the same binding description,
it fires 0 out of 15 and writes a file first in every run. Description wording does not substitute for
it, and removing the hook is what stopped autotriggering.

## The four configurations

Each row is the same prompt, `Let's make a react todo list`, 15 runs, `--max-turns 8`, on a harness with
a neutral working directory, `--setting-sources project`, and a required `superpowers:` prefix, run
outside the sandbox.

| # | configuration | commit | skills | description | fired | premature write | truncated |
|---|---|---|---|---|---|---|---|
| 1 | hook present, original bodies | `615dc8a` | 14 | binding | **15/15** | 0/15 | 0/15 |
| 2 | hook removed, original bodies | `f49f0d7` | 14 | binding | **0/15** | 15/15 | 7/15 |
| 3 | slim tree as shipped | `3882715` | 9 | binding | **2/15** | 13/15 | 7/15 |
| 4 | slim tree, neutral description | `3882715`+swap | 9 | neutral | **0/15** | 15/15 | 7/15 |

Configuration 1 reported `hook ok: 15/15` — every hook invocation succeeded, so row 1 measures a hook
that actually injected.

## What each comparison licenses

Configurations 1, 2 and 3 all carry the same binding description; only 4 differs. That is what makes
these readable.

- **1 vs 2 — the hook.** 15/15 against 0/15, with skills, bodies and description all held constant. The
  hook is not a contributing factor, it is the mechanism. Nothing else in this table moves a number by
  more than 2.
- **3 vs 4 — the description.** 2/15 against 0/15. Two runs apart on 15 samples is inside the noise
  floor stated below. The binding description does not measurably drive a first skill call.
- **2 vs 3 — the rewrite.** 0/15 against 2/15, description held constant. Two variables move (14 skills
  to 9, every body rewritten), so no causal claim is attached, and the difference is noise regardless.

**Decision 4 — that native description-based discovery is sufficient without a hook — is refuted.** The
original control that appeared to vindicate it scored 3/3 on a harness whose working directory named the
skill. Measured honestly, the hookless tree autotriggers in 0 to 2 runs out of 15 and starts writing
code first in 13 to 15 of them.

**`c4ffad9`'s restoration of the binding description bought nothing measurable.** It was justified by a
3/3 that measured the directory name, and the description it restored moves the rate by 2 runs out of 15
against the neutral wording it replaced. That description also summarizes what the skill does, which
CLAUDE.md warns against; it was carrying a cost for no measured benefit.

This does not by itself say the hook should come back. It says the slim set, as shipped, does not
autotrigger, and that any decision to accept or change that should start from these numbers rather than
the old ones.

## Truncation

Configurations 2, 3 and 4 each ended 7 of 15 runs on `error_max_turns`. That does not threaten the
`fired` counts: in all 21 truncated runs across the three configurations, the model had already written
a file before the budget ran out. Zero runs were truncated without either writing a file or invoking a
skill, so no run was cut off before it decided. Raising the turn budget would let those runs build more
of a todo app; it would not change whether a skill fired first.

## Sample size

15 runs per configuration separates roughly 0% from roughly 50%. It does not resolve a 6/15 against a
9/15. Any conclusion drawn here that depends on a difference smaller than that is not supported by these
numbers — which is why 3 vs 4 and 2 vs 3 are read as flat, and why 1 vs 2 at 15/15 against 0/15 is read
as decisive.

## What replaced the old harness

- `tests/claude-code/measure-autotrigger.sh` — reports a rate over N runs; exits non-zero only on broken
  plumbing. Replaced `test-brainstorming-autotrigger.sh`, which asserted firing.
- `tests/claude-code/measure-configs.sh` — the sweep driver for this table.
- `run-skill-tests.sh` — deleted; it wrapped only the demoted test.

`docs/superpowers/plans/2026-08-04-slim-superpowers.md` and `2026-08-04-before.md` still name
`test-brainstorming-autotrigger.sh`. They are executed historical records and were left alone
deliberately.

## Explicit skill requests

`tests/explicit-skill-requests/run-all.sh` reported 4/4 passing on the old harness, but 3 of those 4
invoked a personal `~/.claude/skills` copy rather than this plugin. With `--setting-sources project` and
a required `superpowers:` prefix it reports 4/4 with every hit attributable to this plugin.

Removing the crutch exposed one real harness defect. `use-systematic-debugging` failed at the old default
`MAX_TURNS=3`, ending on `error_max_turns` at `num_turns 4` with nothing fired: its prompt names no
actual bug, so the model spent the budget exploring. At 8 turns the skill fired in 3 of 3 runs. The
default is now 8 and a cutoff prints a NOTE, so it no longer reads as behavioral.

**Naming a skill still works without a hook.** The hook governs whether a skill fires unprompted; it does
not govern whether one fires when the user asks for it by name.
