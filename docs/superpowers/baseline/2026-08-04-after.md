# After — post-rewrite measurements and comparison

**Tree measured:** branch `slim` at the Task 13 commit
**Configuration:** no session-start hook, 9 skills, neutral descriptions
**Claude Code:** 2.1.220
**Date:** 2026-08-04

## Verdict

**The quality criterion did not hold.** `brainstorming` auto-triggers in 4 of 6 runs on the rewritten
tree. A control with the hook removed but the skill bodies untouched triggers in 3 of 3. The rewrite
is the isolated variable.

This is a partial regression, not a collapse — the skill still fires about two thirds of the time —
but the control fires every time, so something binding was lost.

## The three configurations

Each row is the same prompt, `Let's make a react todo list`, asserting `brainstorming` fires with no
`Write`/`Edit`/`NotebookEdit` call before it.

| configuration | hook | skill bodies | passes | turns |
|---|---|---|---|---|
| baseline | present | original | 1/1 | 3 |
| control | removed | original | 3/3 | 8 |
| after | removed | rewritten | 2/3 | 3 |
| after | removed | rewritten | 2/3 | 8 |

**Hook removal alone is clean.** Control 3/3 with the hook gone proves native description-based
discovery is sufficient on this model — decision 4 is vindicated.

**The rewrite is what regressed.** Control 3/3 versus after 4/6, with the hook absent in both.

The most probable single cause is `brainstorming`'s description. The control carries
`"You MUST use this before any creative work - creating features, building components, adding
functionality, or modifying behavior."`; the rewrite carries
`"Use when turning an idea, feature request, or vague goal into a design, before writing code"`.
Descriptions are always in context, so this is the one binding instruction that was present at
trigger time in the control and absent in the after-tree.

Sample sizes are small: 3 versus 6 runs. The direction is consistent but this is not a significant
result in a statistical sense.

## Confounds ruled out

**`--verbose`.** Claude Code 2.1.220 rejects `--output-format stream-json` with `--print` unless
`--verbose` is passed. The very first measurement of this work was a false negative from exactly this.
Both scripts now pass it. Fixed before any baseline was recorded.

**Turn budget.** The first after-failure ended on `error_max_turns` at `--max-turns 3` after three
`ls`/`pwd` calls. Re-running at 8 turns still produced 2/3, and that failure ended on
`subtype: success` at 5 turns — so the regression is not a turn-budget artifact. `max-turns` is now
configurable and the script prints a NOTE when a run ends on `error_max_turns`.

**Sandbox EPERM.** Every nested run in every configuration hit
`EPERM: operation not permitted, mkdir '/Users/hbai/.claude/session-env/...'`, breaking the nested
session's Bash tool. It appears in all 10 logs — passes and failures, control and after — so it is a
uniform degradation, not the discriminator. It is, however, a degraded environment: these numbers
would want re-measuring outside the sandbox before being treated as final.

**Exploring before the skill fires is not new.** The baseline made 2 Bash calls before its Skill call.
The assertion only forbids file mutation, not exploration. Both configurations explore first; only
whether the skill eventually fires differs.

## Recovery options

Per the plan's decision gate, the regression appeared only after the rewrite, so the matching recovery
is at the skill level, not the hook level. Cheapest first:

1. **Restore binding language to `brainstorming`'s description only.** Zero always-on cost —
   descriptions are already loaded. Reverts one field, no body change. This is the single difference
   most likely to account for the result, and the narrowest possible test of that hypothesis.
2. **Restore one-line Iron Laws** to `brainstorming`, `test-driven-development`,
   `systematic-debugging`, and `verification-before-completion`. Roughly 15 words each, about 60 total,
   loaded only on invocation. Recovers the discipline framing without the rationalization tables.
3. **Re-measure outside the sandbox** before either, since the EPERM degradation affected every run.

None applied. This is the decision gate.
