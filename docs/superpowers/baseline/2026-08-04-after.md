# After — post-rewrite measurements and comparison

**Tree measured:** branch `slim` at the Task 13 commit
**Configuration:** no session-start hook, 9 skills, neutral descriptions
**Claude Code:** 2.1.220
**Date:** 2026-08-04

## Correction, 2026-08-06 — every autotrigger number below is refuted

All autotrigger runs on this page were collected through a harness that ran the agent in a directory
under `$TMPDIR/superpowers-tests/<ts>/<test-name>/project`. The agent sees its cwd, so the string
`superpowers-tests` was in context at the moment each run measured whether a skill fired.

Isolated on 2026-08-06, same prompt, same plugins, same model, varying only the cwd name:

| cwd path | invoked `brainstorming` |
|---|---|
| contains `superpowers-tests` | 6/6 |
| neutral name | 0/15 |

Ruled out as alternative explanations: `--max-turns` (3 and 8 both fail on a neutral cwd), log-file
placement, and `/tmp` versus `$TMPDIR`. Session `init` payloads were identical apart from cwd.

The harness was fixed in `a757bc2` — the workspace moved to `$TMPDIR/ws-<ts>-<pid>`, outside the
output directory. The acceptance test then reported **FAIL 0/3**.

What this costs: the 1/1, 3/3, 2/3 and 3/3 in the table below are all measurements of the directory
name, so the difference between configurations carries no information and the conclusion that
`brainstorming`'s description caused the regression is unsupported. It is not disproven either — the
experiment simply did not test it.

The re-measurement ran on Claude Code 2.1.222 and model `claude-opus-5`, so it is not a pure re-run of
the 2.1.220 numbers. Re-measuring all five configurations on the fixed harness is the open work.

## Verdict — refuted, see the correction above

**Regression found, cause isolated, fixed, and re-verified.** The quality criterion now holds.

The rewrite as first written auto-triggered `brainstorming` in 4 of 6 runs, against 3 of 3 for a
control with the hook removed but skill bodies untouched. Restoring `brainstorming`'s original
description — one frontmatter field, no body change — returned it to 3 of 3.

The cause was that single field. Descriptions are always in context, so it was the one binding
instruction present at trigger time in the control and absent after the rewrite. Cost of the fix:
10 words, and zero additional always-on tokens, because descriptions were already loaded.

## The three configurations

Each row is the same prompt, `Let's make a react todo list`, asserting `brainstorming` fires with no
`Write`/`Edit`/`NotebookEdit` call before it.

| configuration | hook | skill bodies | passes | turns |
|---|---|---|---|---|
| baseline | present | original | 1/1 | 3 |
| control | removed | original | 3/3 | 8 |
| after | removed | rewritten, neutral description | 2/3 | 3 |
| after | removed | rewritten, neutral description | 2/3 | 8 |
| **fixed** | removed | **rewritten, original description** | **3/3** | 8 |

**Hook removal alone is clean.** Control 3/3 with the hook gone proves native description-based
discovery is sufficient on this model — decision 4 is vindicated.

**The rewrite is what regressed.** Control 3/3 versus after 4/6, with the hook absent in both.

The cause was `brainstorming`'s description, confirmed by the fixed row above. The control carries
`"You MUST use this before any creative work - creating features, building components, adding
functionality, or modifying behavior."`; the rewrite carries
`"Use when turning an idea, feature request, or vague goal into a design, before writing code"`.
Descriptions are always in context, so this is the one binding instruction that was present at
trigger time in the control and absent in the after-tree.

Sample sizes are small: 3 versus 6 versus 3 runs. The direction is consistent and the fix reproduced
the control exactly, but this is not a significant result in a statistical sense.

## Confounds ruled out

**`--verbose`.** Claude Code 2.1.220 rejects `--output-format stream-json` with `--print` unless
`--verbose` is passed. The very first measurement of this work was a false negative from exactly this.
Both scripts now pass it. Fixed before any baseline was recorded.

**Turn budget.** The first after-failure ended on `error_max_turns` at `--max-turns 3` after three
`ls`/`pwd` calls. Re-running at 8 turns still produced 2/3, and that failure ended on
`subtype: success` at 5 turns — so the regression is not a turn-budget artifact. `max-turns` is now
configurable and the script prints a NOTE when a run ends on `error_max_turns`.

**Sandbox EPERM.** Every nested run in every configuration hit
`EPERM: operation not permitted, mkdir '/Users/hbai/.claude/session-env/...'`, breaking the nested
session's Bash tool. It appears in all 10 logs — passes and failures, control and after — so it is a
uniform degradation, not the discriminator. It is, however, a degraded environment: these numbers
would want re-measuring outside the sandbox before being treated as final.

**Exploring before the skill fires is not new.** The baseline made 2 Bash calls before its Skill call.
The assertion only forbids file mutation, not exploration. Both configurations explore first; only
whether the skill eventually fires differs.

**The confound that was missed: the cwd name.** It was uniform across all configurations here, which
is why it never surfaced as a discriminator — it inflated every row at once. See the correction at the
top.

**Also contaminated, and separately from the cwd name.** No harness isolates `HOME`, so runs inherit

unprefixed. Re-running this suite on 2026-08-06, 3 of the 4 passes invoked a personal copy rather than
this plugin's skill. A `PASS` here is only evidence about this tree if the log shows a `superpowers:`
prefix.

## Recovery applied

Option 1 of three, the narrowest: restore `brainstorming`'s description verbatim to what the control
carried, changing nothing else. Verbatim rather than paraphrased, so the re-measurement tested the
hypothesis instead of introducing a new variable.

Result: 3/3, matching the control. All nine rewritten bodies are kept.

That 3/3 is refuted — see the correction at the top. The restored description is still in the tree, now
as an unmeasured change rather than a verified fix.

The two options not taken, if this ever regresses again:

- **One-line Iron Laws** in `brainstorming`, `test-driven-development`, `systematic-debugging`, and
  `verification-before-completion` — about 60 words total, loaded only on invocation.
- **Re-measure outside the sandbox.** The EPERM degradation affected all runs in every configuration,
  so absolute pass rates here are less trustworthy than the differences between configurations.

## Note on the project's own rule

The restored description both states when to use the skill and summarizes what it does — which
`CLAUDE.md` warns against, because a description that summarizes workflow becomes a shortcut the model
takes instead of reading the body. It was restored verbatim anyway: it is what measured 3/3, and
paraphrasing it would have meant testing a different string than the control used.

Worth a follow-up experiment: a description carrying the binding clause without the workflow summary,
measured the same way. If it holds 3/3, it satisfies both the trigger requirement and the rule.
